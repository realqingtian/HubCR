# D-004 组织角色

[English](d-004-organization-roles.md) | **简体中文**

- 状态：`ACCEPTED`
- 批准日期：2026-08-01
- 决策负责人：产品负责人
- 阻塞内容：成员 Schema、API 与授权矩阵

## 背景

如果每项 MVP 能力没有确定结果，只有角色名称并不足以实现授权。删除、所有权转移、
计费和安全策略执行仍然延后。

## 决策

组织角色使用 `OWNER`、`ADMIN`、`WRITER` 和 `READER`：

| 能力 | OWNER | ADMIN | WRITER | READER |
| --- | --- | --- | --- | --- |
| 查看组织与成员 | 是 | 是 | 是 | 是 |
| 修改组织设置 | 是 | 否 | 否 | 否 |
| 管理 OWNER 或 ADMIN | 是 | 否 | 否 | 否 |
| 邀请/移除 WRITER 或 READER | 是 | 是 | 否 | 否 |
| 创建仓库 | 是 | 是 | 是 | 否 |
| 修改仓库可见性 | 是 | 是 | 否 | 否 |
| 编辑仓库描述 | 是 | 是 | 是 | 否 |
| Push 组织仓库 | 是 | 是 | 是 | 否 |
| Pull 私有组织仓库 | 是 | 是 | 是 | 是 |

每个组织必须至少保留一个 `OWNER`。本记录不会引入仓库删除或所有权转移。

## 备选方案

- 只使用 `OWNER` 与 `MEMBER`：更简单，但无法表达只读访问或委托管理。
- 自定义角色：更灵活，但会在基线得到验证前增加策略 Schema 与 UI。

## 后果

M1 测试必须覆盖每项能力与角色，包括拒绝和成员数据缺失。
