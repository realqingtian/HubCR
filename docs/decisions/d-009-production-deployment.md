# D-009 Production deployment

**English** | [简体中文](d-009-production-deployment.zh-CN.md)

- Status: `ACCEPTED`
- Approved: 2026-08-08
- Decision owner: product owner
- Blocks: M3-07 deployment, migration, and recovery rehearsal

## Context

HubCR needs one explicit MVP deployment contract before backup and restore can be
meaningfully implemented and tested. The local development Compose file previously
started only infrastructure; the API, worker, and Web application remained host
processes. Calling that topology a supported deployment would leave application
images, service ordering, secret mounts, ingress, and recovery boundaries undefined.

## Decision

The first supported MVP deployment target is a single host running Docker Compose.
The production Compose model includes the Go API, worker, migration command, Next.js
Web application, gateway, CNCF Distribution, PostgreSQL, Redis, and MinIO.

Only the gateway publishes a loopback host port. A trusted, operator-managed HTTPS
reverse proxy must terminate TLS and forward the approved public origin to that
listener. HubCR uses secure Web cookies and an HTTPS Registry external origin in this
topology. PostgreSQL, Redis, MinIO, the API, Web application, and Distribution
operations endpoints remain private to the Compose network.

Registry signing material and deployment secrets are supplied outside source control
through protected operator files or environment injection. They are not generated by
production startup and are not included in ordinary data backups.

## Alternatives

- Kubernetes first: rejected for the MVP because it adds ingress, secret-controller,
  storage-class, rollout, and multi-replica decisions before a single-node contract
  is proven.
- Compose and Kubernetes concurrently: rejected because it doubles the supported
  acceptance and recovery matrix.
- Host processes plus an infrastructure-only Compose file: rejected because it is a
  development topology rather than a reproducible deployment contract.

## Consequences

- M3-07 must build and start the complete Compose topology and rehearse recovery
  against its actual PostgreSQL and MinIO boundaries.
- Kubernetes, high availability, multiple replicas, zero-downtime rollout, and
  multi-region operation are not supported MVP claims.
- The process-local authentication limiter remains correct only for this selected
  single-replica API topology. A later multi-replica decision requires shared Redis
  admission state.
- The external TLS reverse proxy, certificates, DNS, host hardening, and encrypted
  off-host backup storage remain operator responsibilities and release limitations.
